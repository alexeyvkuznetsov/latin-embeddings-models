# Latin Embeddings Models

Статические векторные модели латинского языка для историко-семантических исследований. Репозиторий содержит код подготовки корпуса LatinISE, обучения, отбора и валидации моделей, готовые модели и таблицы результатов. Анализ отдельных исторических тем проводится в самостоятельных исследовательских репозиториях. В дальнейшем библиотека может пополняться моделями других латинских корпусов.

## Использование готовых моделей

Каталог: [`models_catalog.csv`](models_catalog.csv). Собственные модели хранятся в `results/selected/`, все 40 независимых запусков — в `results/runs/`. Четыре представительные модели:

| Модель | Срез | min_count | Seed |
|---|---|---:|---:|
| `pre180_mc5.model` | До 180 г. | 5 | 1 |
| `post180_mc5.model` | 180–605 гг. | 5 | 9 |
| `pre180_mc50.model` | До 180 г. | 50 | 7 |
| `post180_mc50.model` | 180–605 гг. | 50 | 3 |

После `pip install -r requirements.txt` из корня репозитория:

```python
from gensim.models import FastText
model = FastText.load('results/selected/pre180_mc5.model')
wv = model.wv
print(wv.most_similar('libertas', topn=15))
```

Для загрузки четырёх моделей из `selection.json`:

```python
from src import core
records, models = core.load_selected()
wv = models[('pre180', 5)].wv
```

Проверяйте наличие леммы через `wv.key_to_index`. В моделях нормализованы регистр и `v → u`; например, `servitus` хранится как `seruitus`. Для готовых моделей не нужны исходные тексты и не требуется повторное обучение. В каталоге указаны Git blob SHA представительных файлов для контроля идентичности. Для воспроизводимых тематических исследований фиксируйте конкретную ревизию библиотеки (после согласованной очистки данных) и сохраняйте параметры анализа.

## Воспроизведение обучения

Источник — лемматизированные тексты LatinISE, опубликованные Лунарди. Версия и происхождение: [`data/README.md`](data/README.md). Сохранена рабочая таблица `data/metadata.csv`. Для получения корпуса из зафиксированной версии источника:

```sh
python download_corpus.py
```

Скрипт проверяет файлы по идентификаторам Git blob, не перезаписывает существующие тексты и загружает только отсутствующие. Это проверка текущих данных, не гарантия идентичности исторической обучающей копии. Нелемматизированные тексты можно дополнительно получить с `--with-originals`.

Затем последовательно выполняются четыре ноутбука в `notebooks/` (Jupyter или Google Colab, путь к проекту — в первой ячейке):

1. `00_prepare_corpus.ipynb` — хронологические срезы, статистика корпуса, списки произведений.
2. `01_train_models.ipynb` — 4 серии по 10 независимых запусков CBOW.
3. `02_select_models.ipynb` — выбор представителя каждой серии по сходству Top-15 соседей (Жаккар).
4. `03_validate.ipynb` — внешний тест синонимов и Opera Latina, диагностические пары, сопоставление с Лунарди.

## Параметры и ограничения

Фиксированы CBOW (`gensim.FastText`, символьные n-граммы отключены), `vector_size=100`, `window=5`, `epochs=10`, `negative=5`, `sample=0.001`, `workers=1` и `seed=1…10`. Срезы определяются по `date_range_end` в `data/metadata.csv`; файлы с пометкой `data_issue` исключаются. Тексты имеют по одному предложению на строку. При чтении леммы приводятся к нижнему регистру, `v` переходит в `u`, удаляется краевая пунктуация. Исходные тексты не переписываются. Ноутбук 00 не проверяет их филологически.

Программа пропускает существующие модели. **Если корпус или настройки обучения менялись, вручную удалите/заархивируйте старые `.model` из `results/runs/` и повторите ноутбуки 00–03.** Автоматической проверки совместимости старых моделей с новым корпусом нет.

- Медоид выбирается по устойчивости соседств, а не по внешнему тесту семантической точности.
- Десять инициализаций оценивают вариативность алгоритма, но не жанровый/авторский состав корпуса (Antoniak & Mimno, 2018).
- Тест синонимов зависит от порога частоты; для `min_count=50` охват мал. Сравнение с *Opera Latina* следует проводить на общих заданиях.
- Хронологические срезы не тождественны христианскому и нехристианскому корпусам.
- Прямые межпериодные косинусы между векторами одной леммы требуют выравнивания; сравнение отношений внутри каждого пространства не требует выравнивания, но зависит от состава корпуса и параметров модели.

Подробности: [`docs/METHODS_ru.md`](docs/METHODS_ru.md), [`docs/REFERENCES.md`](docs/REFERENCES.md). Условия использования сторонних материалов и производных моделей следует сверять с первоисточниками; см. [`data/README.md`](data/README.md).
