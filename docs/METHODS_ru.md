# Краткий методологический протокол

**Корпус.** Подготовленные лемматизированные тексты LatinISE; два среза до 180 г. и 180–605 гг. по дате окончания произведения. Методика разбиения и архитектура — по исследованиям Валентины Лунарди.

**Обучение.** CBOW, 100 измерений, окно 5, 10 эпох, минимум 5 и 50 вхождений, 10 инициализаций на конфигурацию. Статическая модель усредняет разные употребления одной леммы (ср. Sprugnoli et al.; Ehrmanntraut et al.).

**Выбор.** Для каждого периода 300 лемм с частотой ≥50, по 100 из каждой из трёх частотных третей. Для каждого запуска Top-15 соседей, усреднённый коэффициент Жаккара с остальными 9. Выбирается запуск с наибольшим средним. Это наше операциональное решение, основанное на необходимости проверки устойчивости (Antoniak & Mimno, 2018), но не точная процедура, предложенная ими.

**Верификация.** Публикуемый тест синонимов LiLa, сопоставление ранней модели с Opera Latina на общих заданиях (Sprugnoli et al.); описательные лексические пары; качественное сопоставление с примерами Лунарди. Отбор запуска не зависит от результатов этих проверок.

**Воспроизводимость.** Код фиксирует параметры, версии библиотек в requirements.txt, список произведений и результаты всех запусков. Скрипт `download_corpus.py` проверяет текущие исходные файлы по Git blob SHA зафиксированной версии Лунарди; это не ретроспективная проверка исторической обучающей копии. В каталоге моделей указаны Git blob SHA представительных моделей. Изменение исходных файлов требует ручного удаления старых моделей; автоматической гарантии идентичности корпуса нет.

**Ограничения сравнения.** Хронологические срезы не равнозначны разделению по религиозной принадлежности; состав авторов и жанров, включая Вульгату и юридические тексты, требует самостоятельной проверки в тематических исследованиях.
